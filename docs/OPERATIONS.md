# 批次操作

1. 先填写值班员标识，再用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键。执行人自动成为批次责任人。
3. 修复来源文件，重新上传并执行。历史批次保留供复核。
4. 对账无差异且无坏行时可签发。对仍有差异的版本可填写暂缓意见。
5. 导出复核证据并保存于交接记录。

## 交接班

- 复核面板显示当前责任人、守护期截止时间和待办分组；同一批次只有一个有效责任人。
- 下班前点击「交回」释放批次；接班人在复核面板点击「接办」成为新责任人。
- 原责任人未交回且守护期未届满时，接办被拒绝（409）；守护期届满后可直接接办。
- 接办后原责任人的提交一律失效（409 `OWNER_MISMATCH`），新责任人仍须处理完待办分组才能签发。
- 每次认领、接办、交回的责任人与时间记录在「交接记录」中，并随复核证据一并导出。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷。
